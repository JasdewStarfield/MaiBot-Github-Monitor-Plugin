# GitHub 监控插件 2.0.0

监控 GitHub 仓库指定分支，将新提交推送到 MaiBot 群聊。

## 功能与改进

- 同一仓库、同一分支在一轮检查内发现的多条提交合并为一条通知，按旧到新排列。
- 可选让 Maisaka 在每批通知后补一句简短点评；关闭 `enable_commentary` 即只发送基础通知。
- 失败群在后续轮询中重试，已成功群不会因其他群失败而重复收到同一批通知。
- 隔离单个群和仓库的异常，为发送与点评设置超时，避免影响其他仓库的监控。
- 新增 `max_message_chars` 配置，默认 2000，允许 512–4000；超长通知改为提交标题摘要，保留完整记录链接。
- 补充安装与配置说明、直接依赖声明和明确的 Host / SDK 兼容范围。

## 环境要求

- Python 3.12+
- MaiBot Host 1.4.3–1.4.99
- maibot-plugin-sdk 2.22.1–2.22.99
- Python 依赖：`aiohttp>=3.14.3,<4`、`pydantic>=2.11.7,<3`

使用 Manifest v2，面向当前 MaiBot 插件运行环境。安装及配置示例见仓库 README。

## 配置兼容与使用说明

- 保留 `[global_]` 配置及旧的 `[global]` 别名；旧配置未填写 `max_message_chars` 时自动使用默认值。
- 首次启动只建立基线，不补发历史提交。未命中旧提交基线时只通知最新一条。
- 重试状态保存在内存，重启后不会恢复未发送通知；同仓库的失败批次会延迟该仓库后续更新。
- GitHub 接口当前只读取第一页提交；不保证补齐大量积压或停机期间的更新。

已在远端 VPS 的真实 MaiBot 环境中验证仓库推送后的通知发送；自动化回归覆盖汇总、重试、超时、取消、长度限制与配置兼容。
